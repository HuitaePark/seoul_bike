# N01 265곳 규모 검증 — 2026-10-21

최대 구역 N01의 **실제 참조 좌표 265곳·가상 트럭 5대**로 PLAN·REPLAN을 측정했다.
조건별 20회에서 재경로 p95는 **1.88~1.99초**였고 반복·캐시 조건에 따른 전체 계획은 같았다.
현재 기록은 하버사인 추정의 로컬 엔진 결과다. 실제 도로·서버·Kafka·backend·LLM을 포함한
운영 재경로 10초 완료나 새 NFR의 300곳 검증을 뜻하지 않는다.

## 입력과 측정 범위

- 역할 6의 `analysis/out/ref_regions.csv`·`ref_stations.csv`에서 N01 전체 265곳을 읽었다. 원본은 ad17528과 해시가 같다.
- N01 중심점 (37.582815, 127.026664)은 좌표 평균이며 실제 운영 차고지가 아니다.
- 대여소번호 숫자 오름차순에 따라 5대 회수/5대 보충을 번갈아 부여했다. 이 구역의 거치대는 모두 5개 이상이다.
  회수 거점 재고 5대·보충 거점 0대, 트럭 용량 15대·초기 적재 0대·가용 3시간을 가정했다. 현장 관측·예측값이 아니다.
- REPLAN은 차량별 첫 작업 후 느린 차량을 기다리는 가상 스냅샷이다. 완료 5곳·차단 1곳, 방문 후보 259곳,
  경과 593초·차량 적재량 각 5대다. 남은 근무시간·새 위치·완료 재고를 함께 반영했다.
- Darwin arm64, Python 3.12.13, OR-Tools 9.14.6206, solution-limit=50. 기존 하버사인 시속 30km 측정 설정이다.
  후속 main에서 확정된 직선거리 ×1.3·시속 20km 설정의 결과와는 구분한다.
- PLAN → REPLAN 별도 프로세스, 각각 none → cold → warm 순서로 실행했다. 조건별 20회, p95는 nearest-rank의 19번째다.
  입력 구성과 REPLAN 최초 경로 준비(setup_s), warm 준비 호출은 표본에서 제외했다. 프로세스별 메모리에는 포함된다.
- 측정 코드 기준은 main 병합 커밋 66c3e2b와 이번 구현이다. 원시 JSON의 source_sha256으로 정확한 파일을 확인한다.
  조건/실행 순서를 무작위화하거나 외부 부하를 완전히 통제한 비교가 아니다.

## 시간 결과

| 시나리오 | 후보 | 캐시 | 중앙값 ms | p95 ms | 최대 ms |
| --- | ---: | --- | ---: | ---: | ---: |
| PLAN | 265 | none | 1850.71 | 1906.30 | 1955.34 |
| PLAN | 265 | cold | 1869.61 | 1932.00 | 1986.65 |
| PLAN | 265 | warm | 1861.87 | 2007.13 | 2064.34 |
| REPLAN | 259 | none | 1799.62 | 1986.48 | 2142.61 |
| REPLAN | 259 | cold | 1813.33 | 1975.52 | 2247.95 |
| REPLAN | 259 | warm | 1758.19 | 1876.44 | 2127.56 |

none/cold는 조건마다 공급자 호출 20회, warm은 측정 중 공급자 호출 0회·캐시 적중 20회였다.
캐시의 공급자 호출 절감과 전체 지연 개선을 같은 것으로 해석하지 않는다.
PLAN은 작업 700대·미처리 625대·56,901m, REPLAN은 작업 665대·미처리 635대·52,243m다.
작업 대수는 회수·보충 합이며 고유 자전거 수가 아니다. REPLAN 미처리에는 차단 1곳도 포함된다.
265곳을 입력받았다는 뜻이며 제한된 트럭·시간 안에 모든 작업을 처리했다는 뜻은 아니다.

## 메모리와 재현성

전체 프로세스의 최대 RSS는 PLAN **78.80 MiB**, REPLAN **80.02 MiB**였다.
Darwin getrusage(RUSAGE_SELF)의 bytes 값이며 import·입력 준비·warm 준비·세 캐시 조건을 모두 포함한다.
컨테이너/OSRM/브로커 메모리나 행렬만의 증가량은 측정하지 않았다. 운영 서버 자원 예산은 별도 확인한다.

| 시나리오 | 입력 SHA-256 | 전체 계획 SHA-256 |

| PLAN | 65e5e44f78b524ee193523f1312297849b59605ecaf4463c0463e987216ff1ff | 96686a76ba6fd0ec29e0933be213178cfe4e0489bb2a4c0db74397d7d488a137 |
| REPLAN | 7d21783d399496a9b07699867c28d46a491bb22b8c35364341d36f6ed36e26cb | 8e6675dcb2e484f02ece21d10fb1bcc117f5f1ae33fad62f78736908ce65d7ec |

입력 해시에는 실제 참조 중심점·가상 상태·옵션·완료/차단 ID와 원본/ID 대응 해시가 들어간다.
코어 내부 대여소번호와 wire ST-ID를 접두사 규칙으로 바꾸지 않는다. ID 대응 전체는 원본 CSV에 있다.
계획 해시는 차량·방문 순서·도착/출발·적재·미처리 사유를 포함한다. 세 캐시 조건의 각 20회 모두 동일했다.

## 재현

저장소 `or-tools/`에서 Python 3.12 환경으로 실행한다. 원본 CSV가 있는 체크아웃을 사용한다.

```bash
../.venv/bin/python -m rebalancing.benchmark --region N01 --all-candidates \
  --trucks 5 --repeats 20 --scenario plan --cache-mode compare --profile-stages
../.venv/bin/python -m rebalancing.benchmark --region N01 --all-candidates \
  --trucks 5 --repeats 20 --scenario replan --cache-mode compare --profile-stages
```

위 명령은 시간 표본·참조 해시·전체 계획 해시를 재현한다. 호스트별 측정 시각/지연은 달라진다.
원시 JSON의 추가 source_sha256은 기재된 8개 파일의 SHA-256이다. 메모리는 각 명령을 별도 프로세스에서 실행해
Darwin `resource.getrusage(resource.RUSAGE_SELF).ru_maxrss`로 기록했다.
