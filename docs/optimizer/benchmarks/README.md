# 로컬 성능 측정 — 2026-10-21 (KST)

역할 5의 가상 입력·하버사인 추정치에 대한 측정이다. 실제 OSRM·Kafka 대기·backend·LLM은 포함하지 않는다.
운영 재경로 10초 수용 기준을 판정하는 자료가 아니다.

## 실행 조건

- Darwin arm64, Python 3.12.13, OR-Tools 9.14.6206.
- 가상 대여소 200곳·트럭 5대(용량 15대), seed=7, solution-limit=50, all-candidates 입력.
- 각 시나리오·캐시 조건마다 20회. p95는 nearest-rank로 20개 중 정렬한 19번째 값이다.
- PLAN은 한 프로세스에서 none → cold → warm을 순서대로 실행했다.
- REPLAN은 조건별 별도 프로세스로 실행했다. 3개 조건의 입력 해시·결과 계획 해시가 모두 같다.
  최초 compare 실행은 측정 스크립트의 300초 상한에서 중단되어 표본으로 사용하지 않았다.
- REPLAN은 차량별 첫 작업 완료 뒤 대기하는 가상 스냅샷이다. 완료 5곳·진입 불가
  1곳을 제외한 방문 후보는 194곳이며,
  스냅샷 경과 시간은 1091초, 차량별 적재량은 [5, 5, 5, 5, 5]대다.
  현장 관측이나 이동 중 위치 추정값으로 사용하지 않는다.
- 초기 경로 생성·가상 스냅샷 준비(setup_s)와 warm 사전 호출(warmup_s)은 표본에서 제외했다.
- none은 매회 공급자 호출, cold는 매회 새 메모리 캐시, warm은 사전 준비한 같은 메모리 캐시다.
  디스크 캐시와 다른 프로세스의 캐시 재사용은 측정하지 않았다.
- [측정 코드](../../../or-tools/rebalancing/benchmark.py)의 SHA-256: `74f26ea6694fbbf2dfaa9f40f2a516818eb374e78ab7c06f9d6adcc2d5397671`.

## 결과 (ms)

| 시나리오 | 방문 후보 | 캐시 | 중앙값 | p95 | 행렬 p95 | 행렬 외 엔진 p95 |
| --- | ---: | --- | ---: | ---: | ---: | ---: |
| PLAN | 200 | none | 93.43 | 101.72 | 11.99 | 89.93 |
| PLAN | 200 | cold | 93.77 | 96.79 | 16.01 | 80.77 |
| PLAN | 200 | warm | 81.66 | 83.75 | 0.78 | 82.80 |
| REPLAN | 194 | none | 5790.87 | 5942.06 | 11.13 | 5931.21 |
| REPLAN | 194 | cold | 5791.58 | 5987.33 | 16.51 | 5969.45 |
| REPLAN | 194 | warm | 6141.11 | 6370.36 | 1.07 | 6369.80 |

구간별 p95는 서로 다른 표본일 수 있어 더해서 전체 p95로 해석하지 않는다.
행렬 외 엔진 시간에는 입력 준비·검증·모델 구성·탐색·결과 추출이 포함되며 순수 솔버 시간과 다르다.

모든 조건에서 계획은 반복 실행과 캐시 조건에 관계없이 같았다. none/cold의 공급자 호출은 각 20회,
warm은 측정 중 공급자 호출 0회·캐시 적중 20회다. warm 사전 호출은 이 횟수에서 제외했다.
PLAN은 작업 600대·미처리 400대,
REPLAN은 작업 560대·미처리 415대다.
작업 대수는 회수·보충 작업량 합이며 고유 자전거 수가 아니다.

준비된 캐시는 공급자 호출을 없앴지만, 이번 재경로의 전체 p95는 개선되지 않았다. 조건별 실행 순서와
외부 부하를 통제한 실험은 아니므로 차이를 캐시만의 영향으로 단정하지 않는다.
하버사인 기반 재경로에서는 행렬 외 엔진 시간이 전체의 대부분이다. 실제 도로 공급자의 통신 비용·캐시 효과는
도로 데이터와 함께 다시 측정해야 한다. 같은 입력의 계획 보존을 확인한 비교이며 운영 서버 성능이나 최적해를 보장하지 않는다.
