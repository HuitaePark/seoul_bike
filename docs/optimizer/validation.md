# 최적화 코어 검증 기록

- 기준: `5c362d4`에서 시작한 `feat/optimizer-core` 작업
- 일자: 2026-10-20
- 환경: 로컬 macOS ARM64, Python 3.12.13, OR-Tools 9.14.6206
- 기본 설정: 차량 용량 15대, 출발 적재량 0대, 가용 시간 3시간, 해 개수 50
- 이동: 하버사인 거리 + 30km/h 개발용 시간 추정

## 정확성

기존 변경 전 테스트 5개가 통과하는 것을 먼저 확인했다. 운영 상한 변경에 맞춰
기존 기대값을 갱신하고 물리적 시나리오·입력 검증을 추가한 뒤,
Python 3.12에서 **26개 테스트와 24개 subtest가 통과**했다.

- 빈 트럭의 선행 보충 금지, 실제 출발 적재량 유지
- 회수 후 보충 순서, 이종 차량별 용량
- 작업 시간·차고지 복귀 시간·근무 종료 경계
- 현재 위치 출발, 완료/진입 불가 제외
- 완료 회수량을 현재 적재량에 중복 반영하지 않음
- 운영 상한과 거치대 수 분리, 큰 유출 수요의 목표 재고 보존
- 우선순위, 동일 입력 반복, 입력 순서 정규화
- 차량 없음, 잘못된 입력·행렬, 비대칭 이동 시간

CLI의 JSON 출력도 서로 다른 두 프로세스에서 동일한 것을 확인했다.
서드파티 SWIG 모듈의 DeprecationWarning 3건이 있으나 테스트 실패는 없다.

## 로컬 계산 시간

| 입력 | 방문 후보 | 반복 | 중앙값 | 최대 | 미처리 작업 대수 | 동일 결과 |
| --- | --- | --- | --- | --- | --- | --- |
| mock 예측, 대여소 200·트럭 5 | 74곳 | 3회 | 0.0207초 | 0.0226초 | 166 | 예 |
| 전체 후보, 대여소 200·트럭 5 | 200곳 | 3회 | 0.0923초 | 0.0956초 | 400 | 예 |

원본 결과: [mock-200.json](benchmarks/mock-200.json), [stress-200.json](benchmarks/stress-200.json).
출력 해시로 반복 결과를 비교했다. 처리 대수는 회수·보충 작업 합계이며 고유 자전거 수가 아니다.

위 수치는 해당 가상 입력·장비·설정의 단독 측정이다. 실행 전 입력 생성은 제외하며
행렬 준비와 엔진 호출은 포함한다. **Kafka, 실제 OSRM HTTP, 백엔드, LLM은 제외**했다.
따라서 전체 재경로 10초 수용 기준이나 실제 운영 개선율을 달성했다는 뜻은 아니다.

탐색량 100의 전체 후보 입력은 약 10초까지 걸려 초기 기본값을 50으로 조정했다.
탐색량이 늘면 더 많은 작업을 처리하거나 거리를 줄일 수 있지만 응답 시간도 늘어난다.
실제 권역 데이터로 시간·미처리량·거리의 균형을 다시 정해야 한다.

## OSRM·캐시 후속 검증 (최신 main 반영 후)

최신 `origin/main` `221caf5`를 `9460226`에서 개인 브랜치에 병합한 후 진행했다.
같은 Python 3.12.13 환경에서 **77개 테스트와 24개 subtest가 통과**했다.
서드파티 SWIG의 기존 DeprecationWarning 3건만 있으며 실패는 없다.

- OSRM 위도/경도 변환, 중복 좌표 제거·순서 복원, 소수 초·미터 올림
- 일방통행을 표현하는 비대칭 행렬 보존
- 201개 고유 좌표 + 차고지와 같은 위치의 트럭 5대: 요청당 최대 100좌표,
  25개 블록으로 나눈 206×206 행렬이 기대값과 일치
- null·음수·비정상 값·대각선·행렬 크기, HTTP 400/429/503·네트워크 실패 분류,
  시간 예산 초과, 분할 중 데이터 버전 변경 시 전체 거부
- 메모리 복사본 보호, 순서·현재 위치·버전·프로필·스냅 반경별 캐시 무효화
- 만료·손상 캐시 복구, 메모리·디스크 개수 제한, 디스크 실패 시 유효 결과 유지
- **임시 로컬 HTTP 서버**를 통한 실제 urllib → CLI → 두 솔버 실행,
  별도 프로세스의 디스크 캐시 재사용: 최초 HTTP 1회, 재실행 추가 HTTP 0회,
  계획 결과 동일
- 기존 하버사인 기본 CLI의 저녁 입력·적재량 7대 JSON 실행 유지
- 운영 Compose와 신규 개발 Compose의 `config -q`, 전처리 스크립트 구문 검사 통과
- 고정 OSRM 공식 이미지 digest의 AMD64·ARM64 manifest 존재 확인

임시 HTTP 서버는 통신·어댑터 검증용 가짜 도로 행렬을 반환한다. 실제 OSRM의
경로 품질·지도 범위·전처리를 검증한 것은 아니다. 로컬 Docker 엔진이 실행되지
않아 컨테이너 빌드·실행과 실제 PBF 도로 행렬은 이번에 검증하지 않았다.
이 단계의 200곳 분할 테스트도 성능 수용 기준의 측정값이 아니다.
