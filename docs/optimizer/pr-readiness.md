# 역할 5 — 최종 PR 준비 상태 (2026-10-21)

대상은 `hyunmoo` → `main`이다. 이번 작업에서는 PR을 만들지 않고 브랜치에만 커밋·push한다.
최신 반영 기준은 main `134383e`(시간 표기·실시간 화면·시뮬레이터·남은 정책 결정), 병합 커밋 `f1867fa`다.
이번에 추가 확정된 기본값·명칭·운행 설정의 반영은 다음 개발 순서다. 최종 PR 전에 이를 맞추고,
운영 통합의 외부 의존 작업과 구분해 제출 범위를 정한다.

## 현재 브랜치에 준비된 변경

- 지도 최초 범위 맞춤을 버튼 활성화 전에 끝내도록 수정하고 늦은 load의 재확대를 방지했다.
- Kafka producer를 Java와 같은 파티션 선택으로 맞췄다. 실제 6파티션·3토픽·42건으로 확인했다.
- 계획 검토의 예측 구간을 합의된 1~5시간으로 제한했다.
- 날짜·시간별 실수 예측과 데이터 파트의 예측기 출력을 필요량 계산에 연결했다.
  정시 KST·배열/버전 검증·최종 목표 재고 정수 변환을 반영했다. 기존 기본 1시간·구간 끝 정책은 유지한다.
- 서울 17구역·2,716곳 원본 시드를 검증한다. wire의 `ST-` ID와 데이터 대여소번호는 대응표를 사용한다.
- 최대 구역 [N01 265곳 규모 측정](benchmarks/n01-265.md)을 추가했다.
  실제 좌표에 가상 작업량을 결합한 로컬 검사이며 운영 전체 10초 완료를 뜻하지 않는다.
- 최신 계약 버전은 공개 0.12.1·내부 0.7.1·Kafka 0.5.1-draft, payload schemaVersion은 1이다.
  +09:00 생산 의무는 현재 명세상 backend 메시지다. optimizer는 모든 RFC 3339 오프셋을 받고 기존 UTC 결과를 유지한다.

## 최종 PR 제출 직전 남은 일

1. **최신 결정 구현:** 합의 16·17·19·20에 맞춰 기본 예측 3시간, `Station.docks`, 직선거리 ×1.3·시속 20km, 구역별 `trucks_min` 기본값을 적용한다.
   기존 명시 입력은 보존하고 데이터 예측기·시뮬레이터·CLI·테스트 소비처를 함께 확인한다.
   시간별 중간 재고 검사는 합의대로 M4에 진행한다. 비정시 재경로 정렬·운영 상한·우선순위는 생산자와 확인한다.
2. **300곳 기준 검증:** 확정 운행 설정으로 N01 265곳을 다시 측정하고 가상 300곳·5대 검사를 더한다.
   현재 표본은 기존 시속 30km 설정의 265곳 결과이므로 300곳 또는 새 운행 설정 통과로 표시하지 않는다.
3. **제출 상태 정리:** 그 시점의 `origin/main`을 반영하고 영향 범위 검사를 끝낸다. 현재 범위·측정 한계·미구현 통합을 PR 설명으로 정리한다.
   계약을 함께 쓰는 역할 4·6에는 시간별 예측/정수 변환·ID 대응을 검토받는다. 공통 YAML 변경이 필요한 후속은 ROLES의 계약 명세 승인 규칙을 따른다.
4. 사용자 요청 시 PR을 만든다. 실제 도로·업무 연결을 같은 PR의 완료 조건으로 잡을지 별도 통합 PR로 진행할지 범위를 명시한다.

PR 생성 후에는 저장소의 전체 CI(backend Java 25·계약·frontend·Python·Compose)와 리뷰를 통과해야 병합한다.
`hyunmoo` 단독 push는 현재 워크플로에서 GitHub CI를 실행하지 않는다.
로컬에서 실행한 검사와 실행하지 못한 범위는 [검증 기록](validation.md)에 적는다.
