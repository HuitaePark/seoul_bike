# 대여소 ID는 실시간 API ID(`ST-숫자`)로 쓴다

API·Kafka·화면·DB에서 대여소를 가리키는 ID(`stationId`)는 서울시 실시간 대여 정보 API의 ID(`ST-4`)다. 6은 대여소번호(`"102"`, 대여소 이름 앞 번호)를 제안했지만([합의 1번](../data/agreements.md)), Harness 안전 검사(`id_pattern: ST-\d+`), MCP, 승인 카드 화면이 이미 `ST-` 접두어를 전제로 만들어져 있어 고칠 곳이 가장 적은 쪽을 골랐다. 접두어가 있으면 에이전트가 쓴 문장 속에서도 대여소 ID를 자전거 대수 같은 다른 숫자와 구분할 수 있다. 대여소번호는 사람이 읽는 속성(`stationNo`)으로 따로 둔다.

**두 번호는 서로 다른 체계다.** 대여소번호 102는 `ST-4`(망원역 1번출구 앞)이고, `ST-102`는 대여소번호 505(자양사거리 광진아크로텔 앞)다. 운영 중인 2,716곳 가운데 두 숫자가 같은 곳은 하나도 없다. 그래서 한쪽에서 다른 쪽을 문자열로 만들지 않고(`"ST-" + 번호` 금지), 언제나 대응표(`analysis/out/ref_stations.csv`, backend `ref.stations`)로 바꾼다.

## Considered Options

- **대여소번호 `"102"`** (6 제안, 4 찬성): 사람이 아는 번호이고 6의 데이터·대여이력의 기준 키다. 하지만 접두어가 없어 Harness 검사를 인자 칸 기준으로 다시 짜야 하고, MCP·화면·가짜 데이터를 모두 바꿔야 했다.
- **대여이력 API의 5자리 `"00108"`**: 앞의 0이 숫자로 다루는 순간 사라진다.

## Consequences

- 실시간 재고 수집은 API 값을 그대로 쓴다(변환 없음). 대여소번호를 쓰는 데이터(대여이력, 예측기, 시뮬레이터)는 backend나 API로 내보낼 때 대응표로 바꾼다.
- 6의 `ref_stations.csv`는 열 이름을 그대로 둔다: `station_id`가 대여소번호, `api_station_id`가 이 ID다. backend 표는 `station_id` = `ST-4`, `station_no` = `102`로 담는다(이름이 뒤바뀌므로 적재 코드에서 한 번만 맞춘다).
- MCP는 결정 전까지 함께 받던 대여소번호 형식(`108`)을 더는 받지 않는다.
