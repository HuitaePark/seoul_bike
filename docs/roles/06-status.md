## 3. 주요 결과

**실시간 수집과 역산 검증 (예비):** 재고가 거치대 수를 넘는 경우가 32%(고정 회수 대여소 67%)라, 거치대 수를 재고 상한으로 쓰지 않는 PRD 7.1이 맞다. 5분 간격 재고 변화와 대여·반납이 94.7% 일치해 트럭 이동을 직접 관측할 수 있다. 하루치가 쌓이는 10-21, 5~7일치가 쌓이는 10-25~27에 확정한다.

**계획 단위:** 서울 전체를 역산 활동 구역 17개로 나눠 구역마다 계획한다. 개발 기준 구역은 강남-05(영등포·양천, S1 불꽃축제 시나리오 포함)를 제안한다.

**예측 (강남-05, 2025-04~06 검증, 근무조 시작에 예측):**

| 지표 | 베이스라인 (4주 평균) | 예측기 (LightGBM, 예보 날씨 + 오늘 정보) |
| --- | --- | --- |
| 근무조에 빌 대여소 중 미리 잡은 비율 | 40.7% | 50.5% |
| 구역 시간별 대여 수 오차율 | 27.8% | 12.7% |
| 1시간 뒤 → 5시간 뒤 구역 오차율 | 28.3% | 10.7% → 15.4% |

관측 날씨가 아니라 예측 시점보다 앞서 나온 기상청 예보만 쓴다(운영과 같은 조건). 강남-05 모형을 다른 구역에 옮겨 써도 성능이 거의 같다(강북-02: 50.2% vs 자체 모형 51.6%).

**시뮬레이터 (서울 17개 구역, 2025-06-09~15, 하루 평균 실패 대여):**

| 정책 | 실패 (억눌린 수요 보정 후) |
| --- | --- |
| 재배치 없음 | 14,744 |
| 단순 규칙 (빈 곳 채우고 고정 회수 대여소에서 빼기) | 13,688 |
| **본 시스템 (예측 → 목표 재고 → OR-Tools, 매시 다시 계획)** | **12,802** |
| 현행 운영 재현 (역산한 실제 트럭 방문) | 11,477 |

본 시스템은 재배치 없음보다 119개 구역·일 중 118개에서, 단순 규칙보다 105개에서 실패가 적었다. 현행 운영 재현보다는 11.5% 많다.

**현행 운영 재현보다 실패가 많은 이유** (강남-05 1주일 분석, [sim-results.md](../data/sim-results.md) 4절):

1. **근무조 사이에 대비하지 못한다.** 차이의 대부분이 10–12시, 16–18시에서 나온다. 현행 운영 재현의 트럭 이동은 31%가 근무조 밖 시각이다.
2. **공급처에서 아직 많이 뺀다.** 회수처의 실패가 재배치 없음보다도 많다(149 vs 108건).
3. **배치처를 덜 채운다.** 3시간 버틸 만큼만 채운다(+48건). 현행 운영은 방문당 약 13대를 채운다.
4. **비교가 현행 운영에 유리하다.** 역산 방문은 나중에 대여가 일어난 곳에 놓인 배치이고, 대여 기록도 실제 트럭에 맞춰 생겼다.

반대로 현행 운영이 손대지 않는 대여소는 본 시스템이 예측으로 찾아 채워 실패가 적다(−36건).

## 4. 결과를 읽을 때 (발표에 쓸 때)

- **현행 운영 재현은 공정한 비교 상대가 아니라 상한선에 가깝다.** 역산 방문은 "나중에 다른 대여소에서 대여된 자전거"로 거꾸로 추정한 것이라, 실제로 대여가 일어날 곳을 알고 놓은 배치다. 대여 기록도 실제 트럭이 채워 둔 자전거로 생겼고, 트럭 대수·이동 시간 제약도 없다. 공정한 비교는 5절 1번으로 한다.
- **억눌린 수요 보정:** 대여 기록은 자전거가 있을 때만 생긴다. 실제로 비어 있던 시간의 수요(하루 대여 시도의 약 8%)를 만들어 넣은 값이 "보정 후"이고, 근처 대여소로 옮겨 빌린 사람까지 넣어 다소 크게 잡힌다. 효과는 보정 전(하한)과 보정 후 사이로 말한다.
- **판단 지표는 실패 대여다.** PRD의 주 지표(빈 대여소-분)는 이용이 적은 대여소를 채워도 줄어서 함께 보고만 한다.
- **모든 수치는 검증 기간(2025-04~06)이다.** 평가 기간(2025-07~10)은 최종 비교 때 한 번만 쓴다.
- 역산 값(트럭 용량 15대, 근무조, 활동 구역)은 대여이력에서 추정한 값이다. 실시간 수집으로 검증 중이다.

## 6. 직접 돌려 보려면

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python -m sim --terr 강남-05 --date 2025-06-11      # 정책 4종 하루 비교
.venv/bin/python -m forecast.nowcast --terr 강남-05            # 예측기 학습·채점 (약 10분)
```

대여이력과 역산 결과가 있어야 돌아간다(6의 노트북). 실시간 수집은 6의 맥북 cron에서 5분마다 돈다.
