## 1. 개요

### 1.1 목적

PRD의 FR·NFR을 ISO/IEC 25010:2023 제품 품질 모델의 9개 특성과 부특성에 연결한다. 특성마다 **무엇을 재는가 → 목표 → 어떤 증거로 보이는가 → 누가 책임지는가**를 정한다. 발표와 평가에서 "품질을 어떻게 보증했는가"에 이 표 하나로 답한다.

### 1.2 기준 판: 2023

2011판은 철회되었고(ISO 카탈로그 기준), 2023판이 현행이다. 이 제품에는 2023판이 더 맞다.

| 2023판 변경 | 이 제품에서 쓰는 곳 |
| --- | --- |
| **안전성(Safety)** 신설 | FR-14 운전 중 확인 강요 금지(기사 주의 분산은 사람에게 위험), FR-18 승인 보장(무승인 배정 변경은 운영 피해). 2011판에는 이 둘을 담을 특성이 없다 |
| 사용성 → **상호작용 능력**, 포용성·자기 서술성 추가 | 기사 PWA 3터치 보고(FR-11), 작업 이력의 실패 코드 한국어 설명 |
| 보안성에 **저항성(Resistance)** 추가 | 기사 메모 프롬프트 인젝션 방어(FT-05) |
| 이식성 → **유연성**, 확장성 추가 | 워커 수평 확장, 권역·트럭 수 설정 |
| 성숙성 → **무결함성(Faultlessness)** | 시나리오 평가셋 통과율 |

### 1.3 표 읽는 법

| 열 | 내용 |
| --- | --- |
| 부특성 | 2023판 부특성. 한국어는 이 문서의 번역이며 영문 원어를 함께 적는다 |
| 이 제품에서의 의미 | 부특성을 이 제품의 행동으로 바꾼 문장 |
| FR/NFR | [PRD](PRD.md) 3·4절 ID. 아키텍처 제약이라 ID가 없으면 `-` |
| 측정·목표 | 지표와 목표. 조정 가능한 값은 `초기값` |
| 증거 | 테스트, 평가 시나리오(`SC-`·`FT-`, [HARNESS 6.2](HARNESS.md#62-시나리오)), LangSmith 지표, 시뮬레이터 지표([PRD 9.2](PRD.md#92-지표)), 감사 로그 |
| 담당 | 역할 번호 ([1.4](#14-역할-번호)). `화면 담당`은 해당 화면을 맡은 역할이며, 2는 측정·판정만 한다 |

### 1.4 역할 번호

팀에서 확정한 6인 분담을 따른다. [ROLES](ROLES.md)의 번호와 다를 수 있으며, ROLES 갱신 전까지 이 표가 기준이다.

| # | 역할 | 이 문서와 관련된 책임 |
| --- | --- | --- |
| 1 | 에이전트 그래프 | LangGraph, 도구 선택, interrupt·재개, 진행 이벤트 |
| 2 | Harness · 평가 · 품질 | Harness 8요소, LangSmith, 시나리오 평가셋, 이 매핑. 화면은 맡지 않고 화면 지표를 측정·판정한다 |
| 3 | MCP · RAG | `business-mcp`, `rag-mcp`, 근거 문서, 색인 |
| 4 | 백엔드 | Spring Boot, 인증, 작업 API, SSE, Kafka 재시도·DLQ, 수집 스케줄러 |
| 5 | 최적화 · 인프라 | OR-Tools, OSRM, solve 소비, Compose, CI |
| 6 | 데이터 분석 · 시뮬레이터 | 역산 검증, 수요 예측, 대여소 분석, 시뮬레이터, 정책 비교 |

## 2. 특성 요약

| 특성 | 원어 | 관련도 | 핵심 요구 | 대표 지표 |
| --- | --- | --- | --- | --- |
| 기능 적합성 | Functional suitability | 높음 | FR-02, FR-03, FR-16, NFR-07 | P0 수용 기준 통과율, 숫자 출처 채점 |
| 성능 효율성 | Performance efficiency | 높음 | NFR-01, NFR-02, FR-06 | 재경로·초안 생성 p95, 작업당 토큰 |
| 호환성 | Compatibility | 중간 | FR-06 | 계약 테스트 통과, MCP 도구 발견 |
| 상호작용 능력 | Interaction capability | 높음 | FR-04, FR-11, FR-13 | 보고 터치 수, 처음 쓰는 사용자 완료율 |
| 신뢰성 | Reliability | 높음 | NFR-03, NFR-05 | LLM 차단 시 핵심 흐름, 재개 일치, DLQ 유실 |
| 보안성 | Security | 높음 | NFR-06, NFR-05, NFR-07 | 401·403 시험, trace 개인정보 0건, FT-05 |
| 유지보수성 | Maintainability | 중간 | FR-07 | 설정만으로 한도 변경, FAILED 진단 경로 |
| 유연성 | Flexibility | 중간 | FR-17 | 가짜 모델로 FT 자동 실행, `docker compose up` 1회 |
| 안전성 | Safety | 높음 | FR-14, FR-18, NFR-03 | 무승인 변경 0건, 운행 중 모달·소리 0건 |

관련도 `중간`은 평가표 배점과 직접 닿지 않거나 시연 범위에서 위험이 작다는 뜻이다. 생략하지 않고 최소 지표 하나를 둔다. 부특성 단위의 `낮음`은 각 표에 이유를 적는다.
