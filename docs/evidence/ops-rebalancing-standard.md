# 재배치 운영 기준

> 팀 저장소(PRD v0.2, ROLES v0.2)를 **기본 근거**로 정리한 운영 기준이다. 각 절 끝에 출처를 적었다.
> `[보조]`는 저장소 밖 자료(논문, 서울시 보도자료)에서 온 내용이고, `[초기값]`은 인터뷰·시뮬레이터로 조정할 값이다.
> 공개 자료가 아닌 실제 운영 매뉴얼이 없으므로, 이 문서는 공개 자료와 팀 분석을 근거로 팀이 만든 기준이다.

## 1. 적용 범위

재배치 계획은 권역 하나 단위로 세운다. 권역은 구 1~3개, 대여소 100~200곳, 트럭 3~5대 규모다. 데모 권역 후보는 광진·성동이다 (역산 분석에서 회수·배치 상위 대여소가 많다).

출처: PRD 7.2, ARCHITECTURE 13

## 2. 역할과 결정 원칙

- 숫자(재고, 대수, 경로, 우선순위)는 코드가 계산한다. LLM은 자연어 요청과 현장 메모를 구조화된 제약 조건으로 바꾸고 설명 문장을 쓴다. 결정은 사람이 한다.
- 계획 활성화와 경로·배정 변경은 사람의 승인 이벤트 없이 일어나지 않는다. 무승인 변경 건수는 반드시 0이다.
- 관제 관리자는 계획을 승인하고 큰 변경을 승인한다. 트럭 기사는 작은 변경을 수락·거절하며, 자기 트럭의 경로와 제안만 본다.
- LLM이 실패해도 계획 생성·승인·보고·재경로는 동작하고, 설명은 템플릿 문장으로 대체한다.

출처: PRD 5.1, FR-18, NFR-03, NFR-06, NFR-07, 9.2

## 3. 근무조

| 근무조 | 작업 시간 `[초기값]` | 계획 초안 생성 |
| --- | --- | --- |
| 오전 | 07–10시 | 06:30 |
| 오후 | 13–16시 | 12:30 |
| 저녁 | 19–20시 | 18:30 |

- 근무조 시간은 2025 대여이력 역산으로 추정한 값이다. 밤(22~06시) 작업은 확실한 방문의 약 2%뿐이라 근무조로 두지 않았다. 다만 시각이 1시간 안으로 좁혀지는 방문만으로 추정해 밤 작업이 적게 잡혔을 수 있다.
- 트럭 수는 근무조별 설정값이다. 성수기(4~10월) 하루 재배치량은 약 4,100~4,900대, 12~2월은 약 1,700~1,900대로 계절 차이가 크기 때문이다.
- `[보조]` 2019년 기준 서울시설공단 재배치 인력은 배송 직원 136명, 배송센터 11곳(강북 5, 강남 6)이었다. 시뮬레이터 인력·차고지 규모를 가정할 때 참고한다.

출처: PRD 1.5, 7.4 · 보조: ref-forecast-kim-2023 6절

## 4. 목표 재고와 필요 대수

1. 대여소별로 앞으로 `H시간` 동안의 대여·반납을 예측해 예상 재고 변화를 계산한다. `H` 초기값은 3시간이다.
2. 예상 재고가 `[하한, 운영 상한]`을 벗어나지 않도록 목표 재고 범위를 정한다. 지금 재고가 범위를 벗어난 만큼이 필요 대수다. 남으면 회수(pickup), 모자라면 배치(dropoff)다.
3. **운영 상한은 하드 제약이 아니라 설정값이다.** 초기값은 거치대 수다. 역산 결과 회수 직전 재고 중앙값이 31대로 거치대 중앙값 10개의 약 3배였기 때문에, 거치대 수를 넘는 재고가 반납을 막는지 실시간 수집으로 검증한 뒤 조정한다.
4. 하한에는 예측 오차를 덮는 안전 재고(`safety`)를 둔다.

- `[보조]` 2019년 연구는 대여소별 적정 거치율 60%를 안전재고 목표로 썼다. 비교 기준값으로만 쓰며, 위 3번의 역산 결과와 충돌하므로 그대로 채택하지 않는다.
- `[보조]` 같은 연구에서 1시간 예측 오차(RMSE)는 대여 2.336, 반납 2.343으로 대여소·시간당 약 2대였고, 거치대와 수요가 큰 대여소일수록 오차가 컸다. 따라서 안전 재고는 대여소 규모가 클수록 키우는 것이 합리적이다 (팀 해석).
- `[보조]` 같은 연구는 3~5시간 앞을 매시간 다시 예측했다. `H = 3` 초기값과 맞는다.

출처: PRD 7.1, ortools-rebalancing 3절 · 보조: ref-forecast-kim-2023 5·6·8절

## 5. 우선순위

- 우선순위 점수 = 부족 대수 × 수요 강도 × 임박도 × 유형 가중치.
- **빈 대여소 위험의 가중치를 과적재보다 높게 둔다.** 대여를 못 하는 불편이 반납 혼잡보다 직접적이기 때문이다.
- 점수와 구성 요소를 근거로 저장하고, 계획의 각 정류장에 현재 재고, 예측 재고, 예상 빈 시각 또는 과적재 정도, 대여소 역할, 고도, 우선순위 점수, 적용된 제약 조건을 표시한다.
- 하루 평균 불균형이 `10대 이상 [초기값]`이고 방향이 일정한 대여소는 고정 회수·고정 배치로 표시한다. 예측이 비어 있거나 불확실하면 역할 방향을 기본값으로 쓴다.

출처: PRD 7.1, FR-03

## 6. 트럭과 경로

| 항목 | 기준 `[초기값]` | 비고 |
| --- | --- | --- |
| 트럭 용량 | 15대 | 역산에서 방문 묶음이 13~15대에 몰리고 15대를 넘으면 급감. 현재 mock 코드는 20대이며 PRD v0.2에 맞춰 바꿀 예정 |
| 적재 범위 | 0대 ~ 트럭 용량 | 회수 +q, 배치 -q로 누적. "실어야 내려놓을 수 있다"는 순서가 자동으로 지켜짐 |
| 정차 시간 | 3분 + 대당 0.5분 | 실제 값은 인터뷰로 확인 |
| 시간 상한 | 근무조 종료 시각 | |
| 출발 | 트럭 현재 위치, 현재 적재량 | |
| 도착 | 차고지 또는 자유 종료 | |
| 거점 포기 | 벌점 = 우선순위 점수 | 빠진 거점과 점수, 사유(적재량 한계·시간 한계)를 관리자에게 표시 |
| 재경로 | 완료 정류장을 빼고 현재 위치·적재량에서 다시 풀이 | |
| 탐색 한도 | 시간이 아닌 해 개수로 고정 | 같은 입력이면 같은 계획 (재현성) |

출처: PRD 1.5, 7.2, FR-05, NFR-04, ROLES 3절 5, ortools-rebalancing 3절

## 7. 제약 조건

관리자 요청과 기사 현장 보고는 같은 형식의 제약 조건으로 바뀐다. 각 제약에는 대상 대여소, 유효 기간, 출처(관리자·기사·시스템), 사유가 들어간다.

| 유형 | 뜻 | 대표 상황 |
| --- | --- | --- |
| `target_adjust` | 목표 재고 가감 | 행사, 날씨 |
| `station_suspended` | 운영 기관이 대여·반납을 일시 중지 | 서울세계불꽃축제 |
| `station_blocked` | 트럭 진입 불가 | 기사 현장 보고 (공사, 통제) |
| `inventory_override` | 현장 실제 재고로 보정 | 기사 보고 "앱 8대, 실제 3대" |
| `priority_boost` | 관리자 지정 우선 | 관리자 판단 |

- `station_suspended` 기간에는 해당 대여소 수요를 0으로 보고 배치 대상에서 뺀다. **사전 회수 여부는 관리자가 정한다.**
- LLM이 만든 제약은 스키마로 검증한다. 목표 재고 변경 폭이 운영 상한을 넘거나 권역에 없는 대여소 ID가 있으면 거부하고, 관리자 확인 후에만 반영한다.
- `[보조]` 2025 불꽃축제 때 서울시는 여의도·마포·용산·동작 일대의 공유자전거 대여·반납을 9월 26일 19시부터 9월 28일 09시까지 중단했다. 행사 당일만이 아니라 **전날 저녁부터 다음 날 아침까지** 걸치므로, 유효 기간을 행사 시간보다 넓게 잡는다.

출처: PRD 6.4, 6.8, 2.1 S1·S2 · 보조: notice-seoul-fireworks-2025

## 8. 변경 등급과 승인 (작은 변경·큰 변경)

| 등급 | 조건 `[초기값]` | 승인 |
| --- | --- | --- |
| none (변경 없음) | 정류장 순서·대수 변화 없음 | 없음 |
| minor (작은 변경) | 같은 트럭 안의 변경, 빠지는 정류장 2곳 이하, 소요 시간 증가 10분 이하 | 기사 |
| major (큰 변경) | 트럭 간 배정 이동, 트럭 추가 투입, minor 기준 초과, 관리자 요청에서 비롯된 변경 | 관리자 → 기사 |

- 경로 변경의 승인 카드가 곧 기사 수락이다. 큰 변경은 관리자 카드가 승인된 뒤 기사 카드를 한 장 더 보낸다. 앞 카드가 거절되면 기존 경로를 유지한다.
- 같은 트럭에 새 변경안이 생기면 이전 대기안은 무효(`superseded`)가 된다.
- 기사가 거절하면 기존 경로를 유지한다.
- 등급 판정은 코드 규칙(백엔드)이 한다. 경계값은 현장 인터뷰로 확인한다.

출처: PRD 6.6, 6.3, FR-07(작은 변경·큰 변경), FR-13 · specs openapi v0.3 ApprovalRequest(큰 변경은 관리자 → 기사 카드 두 장)

## 9. 현장 보고와 기사 안내 (운전 중 알림 금지)

- 기사는 정류장에서 실제 수량을 3번 이하의 터치로 보고한다. 기본값은 계획 수량이고 +/-로 조정한다.
- 진입 불가·공사 등은 선택지 또는 짧은 메모로 남긴다. 메모는 LLM이 `{유형, 대여소}`로 바꾸고, 남은 경로를 다시 계산한다.
- **운전 중 확인을 강요하지 않는다.** 운행 중에는 모달·소리 알림 없이 배지만 표시한다. 변경안은 정차 중이거나 정류장에 도착했을 때만 보여준다.

출처: PRD FR-11, FR-12, FR-14, 6.3

## 10. 재계산 기준 (미확정)

저장소에는 "얼마나 어긋나면 다시 계산하는가"의 수치 기준이 아직 없다. 아래는 보조 근거로 만든 **팀 제안**이다.

- 현장 재고가 예상과 **2~3대 이상** 차이 나면 남은 경로를 다시 계산한다. 근거: 2019년 연구의 1시간 예측 오차가 약 2대였다 `[보조]`.
- 이 오차는 1시간 기준이므로 가까운 정류장에 맞는 값이다. 도착 예정 시각이 먼 정류장일수록 기준을 넓히는 규칙이 필요하다 (논문에 없는 팀 추론). 계수는 시뮬레이터로 정한다.

출처: 보조: ref-forecast-kim-2023 5·9절

## 11. 성능 기준

| 항목 | 기준 `[초기값]` |
| --- | --- |
| 재경로 응답 | 대여소 200곳·트럭 5대 기준, 현장 보고부터 변경안 생성까지 10초 이내 |
| 계획 초안 생성 | 같은 규모에서 60초 이내 |
| 진행 상황 반영 | 트럭 위치·완료 정류장·대기 변경안을 5초 이내 지연으로 반영 |

출처: PRD NFR-01, NFR-02, FR-06

## 12. 아직 확인하지 않은 가정

- 트럭 용량 15대가 실제 용량인지, 15대 묶음이 운영 규칙인지
- 거치대 수를 넘어 반납할 수 있는지 (회수 직전 재고 중앙값 31대 추정의 검증)
- 근무조가 07–10시, 13–16시, 19–20시 세 개인지, 밤 작업이 있는지
- 작은 변경·큰 변경의 경계를 현장에서 받아들이는지
- 트럭이 부족할 때 현장에서 쓰는 우선순위 기준이 있는지
- 정차 시간의 실제 값

출처: PRD 13
