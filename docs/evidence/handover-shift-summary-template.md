# 근무조 인수인계 요약 양식

> 근무조가 끝날 때(`shift_end`) 에이전트의 `summarize` 노드가 이 양식으로 요약과 인수인계 메모를 만든다.
> 양식의 항목은 저장소 PRD의 State·감사 로그·지표를 **기본**으로 정했다. 숫자는 모두 코드가 채우고, LLM은 "다음 근무조에 전할 말"과 요약 문장만 쓴다.

## 1. 왜 필요한가

PRD가 정의한 문제 중 하나는 "판단 근거가 남지 않음"이다. 왜 이 거점을 먼저 갔는지 기록되지 않아 검토와 인수인계가 어렵다. 이 양식은 근무조 하나의 계획, 변경, 포기 거점, 현장 사정을 다음 근무조가 5분 안에 파악하도록 정리한다.

출처: PRD 1.1, 1.3 목표 3, 6.3 `summarize`

## 2. 작성 규칙

- **숫자는 코드가 채운다.** 재고, 대수, 시간, 지표는 State와 감사 로그에서 가져오고, LLM은 숫자를 새로 만들지 않는다.
- **LLM이 실패하면** 3~7절은 그대로 두고 8절 "다음 근무조에 전할 말"을 템플릿 문장으로 대신한다.
- 기사 이름·연락처는 넣지 않는다. 트럭은 트럭 ID로만 적는다.
- 체크포인트는 감사 로그가 아니다. 이 요약은 별도 append-only 업무 기록에 저장하고, 근무조 단위로 조회할 수 있어야 한다.

출처: PRD NFR-03, NFR-05, NFR-07, 6.8 · ROLES 3절 2 Guardrails(마스킹)

## 3. 양식

```markdown
# 근무조 인수인계: {권역} {날짜} {근무조}

## 1. 개요
- 근무조 ID: {region}:{date}:{shift}
- 작업 시간: {시작} ~ {종료}
- 투입 트럭: {대수}대 ({트럭 ID 목록})
- 최종 계획 버전: v{plan.version} (승인: {승인 시각}, 승인 주체: 관리자)

## 2. 결과 지표 (코드 계산)
- 이동 자전거: {합계}대 (회수 {n}대 / 배치 {n}대)
- 완료 정류장: {완료}/{계획} 곳
- 빈 대여소-분: {값}분
- 과적재 대여소-분: {값}분
- 트럭-시간당 해소 대수: {값}대
- 무승인 변경 건수: {값}건 (반드시 0)

## 3. 처리하지 못한 거점 (다음 근무조 우선 검토)
| 대여소 | 필요 대수 | 우선순위 점수 | 사유 |
| {station_id} {이름} | {±n}대 | {score} | 적재량 한계 / 시간 한계 / 관리자 제외 |

## 4. 계획 변경 이력
| 시각 | 트럭 | 등급 | 내용 | 결과 |
| {hh:mm} | {truck_id} | minor/major | {빠진·추가된 정류장, 소요 시간 변화} | 수락 / 거절 / 무효 |

## 5. 현장 보고 요약
| 시각 | 대여소 | 유형 | 내용 |
| {hh:mm} | {station_id} | 재고 불일치 / 진입 불가 / 공사 / 기타 | {예: 앱 8대, 실제 3대} |

## 6. 다음 근무조까지 유효한 제약
| 유형 | 대여소 | 유효 기간 | 출처 | 사유 |
| station_suspended 등 | {ids} | {from} ~ {to} | 관리자 / 기사 / 시스템 | {reason} |

## 7. 데이터 상태
- 마지막 실시간 재고 수집: {시각}
- 예측 발행 시각 / 모델 버전: {시각} / {version}
- 재고 차이가 큰 대여소: {station_id: 시스템 n대 vs 현장 m대}

## 8. 다음 근무조에 전할 말 (LLM 작성, 3문장 이내)
{요약 문장}

## 근거
- 계획: plan v{n}, 감사 로그 {audit_id 범위}
- 참고 문서: {doc_id 목록}
```

| 1 개요 | `ShiftState.shift_id`, `plan.version`, 승인 감사 이벤트 | 6.1, 6.4, FR-18 |

| 3 처리하지 못한 거점 | `plan.unserved` (사유 포함) | 7.2, FR-05 |

## 5. 작성 예시 (가상 데이터)

> 아래 숫자는 양식 이해를 돕는 **가상 값**이다. 실제 운영 근거로 인용하지 않는다.

```markdown
# 근무조 인수인계: 강북-02 2026-10-21 오전

## 1. 개요
- 근무조 ID: N02:2026-10-21:AM
- 작업 시간: 07:00 ~ 10:00
- 투입 트럭: 3대 (TR-01, TR-02, TR-03)
- 최종 계획 버전: v4 (승인: 06:52, 승인 주체: 관리자)

## 2. 결과 지표
- 이동 자전거: 96대 (회수 50대 / 배치 46대)
- 완료 정류장: 17/19곳
- 무승인 변경 건수: 0건

## 3. 처리하지 못한 거점
| ST-102 | -4대 | 21.0 | 시간 한계 |
| ST-97 | +6대 | 18.5 | 적재량 한계 |

## 4. 계획 변경 이력
| 08:06 | TR-01 | minor | ST-3390 이후 정류장 1곳 제외, +6분 | 수락 |

## 5. 현장 보고 요약
| 07:58 | ST-3390 | 재고 불일치 | 앱 3대, 실제 0대 |

## 6. 다음 근무조까지 유효한 제약
| station_blocked | ST-1660 | 10-21 07:30 ~ 10-22 18:00 | 기사 | 진입로 공사 |

## 8. 다음 근무조에 전할 말
ST-1660은 공사로 진입 불가가 내일 저녁까지 이어집니다. 오전에 처리하지 못한 ST-102(배치 4대)을 오후 계획에서 먼저 검토해 주세요. ST-3390은 앱 재고가 실제보다 높게 나오니 현장 확인이 필요합니다.
```

## 6. 열린 항목

- 근무조가 07–10시, 13–16시, 19–21시로 짧고 사이 공백이 길다. 공백 동안 생긴 위험(실시간 수집 결과)을 다음 근무조 요약에 덧붙일지 정해야 한다.
- 2절 지표 중 빈 대여소-분·과적재 대여소-분은 실운영에서는 실시간 재고로, 시뮬레이터에서는 재생 결과로 계산한다. 어느 쪽 값인지 표시한다.
