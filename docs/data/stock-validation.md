# 역산 재고 검증

| 항목 | 내용 |
| --- | --- |
| 문서 상태 | 예비 결과 (2026-10-20, 수집 1시간 남짓). 확정은 수집 5~7일 뒤 |
| 만드는 코드 | `analysis/validate_stock.py` |
| 검증 대상 | PRD 1.5의 역산 추정(방문 직전 재고, 방문당 대수, 근무조), 거치대 수가 재고 상한인지 |

**지금까지의 결론 (예비):** 재고가 거치대 수를 넘는 일은 흔하다. 실시간으로 관측한 트럭 방문의 직전 재고와 방문당 대수도 역산 추정과 가깝다. 다만 아직 한 시간 남짓이라 확정하지 않는다.

## 방법

1. **거치대 초과:** 5분 간격 실시간 재고에서 재고가 거치대 수(`rackTotCnt`)를 넘는 비율을 센다. 대여이력이 필요 없다.
2. **트럭 사건:** 대여소마다 연속한 두 스냅샷 사이의 `재고 변화 − (반납 − 대여)`가 트럭이 넣거나 뺀 대수다. 같은 시각의 대여이력은 서울 API `tbCycleRentData`로 받는다. 절댓값이 3대 이상인 구간을 트럭 사건으로 보고, 같은 대여소에서 15분 안에 이어지면 한 방문으로 합친다.
3. **주의:** 대여이력 API는 반납이 끝난 대여만 준다. 최근 구간은 대여가 덜 잡혀 회수처럼 보이므로, 실행 시각보다 2시간 이상 지난 구간만 쓴다. 같은 대여소에 1분 이하로 반납한 대여는 뺀다.

## 예비 결과 (2026-10-20 14:26~15:50)

**① 거치대 초과 (스냅샷 19개 × 2,716곳)**

| 항목 | 값 |
| --- | --- |
| 재고가 거치대 수를 넘은 비율 | 32.1% |
| 고정 회수 대여소에서 넘은 비율 | 66.8% |
| 고정 회수 대여소의 재고 ÷ 거치대 (상위 10%) | 3.7배 |
| 가장 많은 재고 | 231대 (LG사이언스파크 E14동, 거치대 57개) |

역산의 "회수 직전 재고가 거치대의 약 3배"와 같은 방향이다. 거치대 수를 재고의 하드 상한으로 쓰지 않는 PRD 7.1의 설계가 맞다.

**② 트럭 사건 (14~15시)**

코드가 도는지 보려고 성숙 기준을 2시간에서 24분으로 낮춰 돌린 값이다. 결론에는 쓰지 않는다.

| 항목 | 관측 | 역산 추정 (2025) |
| --- | --- | --- |
| 재고 변화와 대여·반납이 정확히 맞는 구간 | 94.7% (1대 이내 99.1%) | |
| 배치: 방문 수 / 대수 중앙값 | 74 / 13대 | 13대 |
| 배치 직전 재고 중앙값 / 0대 비율 | 4대 / 19% | 2대 / 30% |
| 회수: 방문 수 / 대수 중앙값 | 56 / 10.5대 | 13대 |
| 회수 직전 재고 중앙값 / 거치대 이상 비율 | 28대 / 89% | 31대 / 96% |

재고 변화와 대여·반납이 구간의 94.7%에서 정확히 맞아서, 이 방법으로 트럭 이동을 정밀하게 관측할 수 있다. 방문 하나에 20대 넘게 옮긴 경우는 트럭 두 대가 같은 대여소에 들렀거나 15분 안 합치기가 겹친 것으로 보인다.

## 다시 돌릴 때

```bash
.venv/bin/python analysis/validate_stock.py
```

| 시점 | 확인할 것 |
| --- | --- |
| 2026-10-21 (하루치) | 시각별 트럭 사건으로 근무조(07–10, 13–16, 19–20시) 확인 |
| 2026-10-25 ~ 27 (5~7일치) | 방문 직전 재고, 방문당 대수, 하루 재배치량을 구역별로 확정하고 역산 추정과 비교. 운영 상한(PRD 7.1)과 트럭 용량 15대 결정 |

관측한 트럭 사건은 `data/derived/truck_events.csv`에 남는다. 이후 시뮬레이터의 현행 운영 재현을 역산 방문 대신 관측 방문으로 검증하는 데 쓴다.
