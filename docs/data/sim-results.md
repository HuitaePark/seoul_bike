# 시뮬레이터 결과

| 항목 | 내용 |
| --- | --- |
| 문서 상태 | 초안 v0.1 (2026-10-20). 모두 검증 기간(2025-04~06) 결과다. 평가 기간(2025-07~10)은 아직 쓰지 않았다 |

**결론:** 서울 17개 구역 1주일(2025-06-09 ~ 15)에서 본 시스템은 재배치 없음보다 실패 대여를 13% 줄이고(구역·일 119개 중 118개), 단순 규칙보다 6% 줄였다(105개). 현행 운영 재현보다는 11.5% 많다(21개에서만 적었다).

실패 대여는 억눌린 수요 보정 후 값이다. 보정 전(효과의 하한)은 함께 적었다. 현행 운영 재현은 대여 기록이 실제 트럭 이동에 맞춰 생겨 구조상 유리하다([data-spec.md](data-spec.md) 7절).

## 2. 본 시스템 설정 고르기 (강남-05, 2025-06 8일)

| 변형 | 공급처 | 계획 | 실패 (보정 후) | 옮긴 대수 |
| --- | --- | --- | --- | --- |
| A | 고정 회수 대여소 9곳 | 근무조마다, 근무조 끝까지 | 1,298 | 197 |
| B | 2024 회수처 41곳 | 근무조마다, 근무조 끝까지 | 1,306 | 264 |
| C | 2024 회수처 | 매시, 근무조 끝까지 | 1,322 | 354 |
| **D (채택)** | 2024 회수처 | **매시, 늘 3시간 앞까지** | **1,248** | 315 |
| (참고) | 재배치 없음 / 단순 규칙 / 현행 운영 | | 1,430 / 1,358 / 1,143 | |

- **공급처를 전해 회수처로:** 고정 회수 대여소(2025년 4~10월 자료)는 평가하는 6월이 섞여 있어 2024년 역산 회수처로 바꿨다. 공급처만 넓히면(B) 옮긴 대수는 늘지만 실패는 비슷하다.
- **매시 다시 계획:** 그 시각의 실제 재고와 새 예측으로 다시 짜면, 비기 직전에 도착하게 할 수 있다. 다만 근무조 끝까지만 보면(C) 마지막 시간에 1시간만 보게 되어 다음 시간대를 대비하지 못한다. 늘 3시간 앞을 보는 D가 가장 낫다(8일 중 6일 A보다 적음).
- 처음 설정(회수 제한 없음)은 회수한 대여소의 실패가 재배치 없음보다 124~223건 늘어, 공급처를 정해 두는 규칙이 생겼다.

강남-05 2025-06 한 달(30일)의 A 설정 결과: 하루 평균 실패(보정 후) 1,108건, 재배치 없음 1,203, 단순 규칙 1,154, 현행 운영 975 (`data/derived/sim_강남-05_2025-06-01_2025-06-30.csv`).

## 4. 현행 운영과의 차이, 다음 개선

| 원인 후보 | 근거 | 다음 |
| --- | --- | --- |
| 공급과 배치를 정하는 규칙 | 트럭을 3대에서 8대로 늘려도 실패가 1~5%만 줄었다. 현행 운영은 하루 4,634대, 본 시스템은 3,616대를 옮긴다 | 공급처 후보를 예측 여유로 걸러 넓히기, 배치량을 다음 근무조까지 버티게 |
| 경로에 시간 차원이 없음 | 매시 다시 계획(D)만으로 4% 줄었다 | 5의 OR-Tools PRD v0.2(시간 차원, 우선순위 벌점, 트럭 현재 위치에서 재경로)를 받으면 바꾼다 |
| 재생의 구조적 유리함 | 현행 운영의 보정 전 실패는 916건으로 다른 정책의 1/4 | 실시간 수집으로 관측한 트럭 방문으로 현행 운영을 다시 재생해 비교 |
| 대여소 예측 오차 | 우연에 의한 바닥이 커서 대여소 하나는 크게 틀린다 | 회수량에 여유(z)를 두는 방식 유지, 구역 단위 정보 활용 |
